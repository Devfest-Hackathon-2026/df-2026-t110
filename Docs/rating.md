# 対戦結果・レーティング・ランキング機能 Design Doc

## 目的

- 実力をある程度反映しつつ、試行錯誤や継続的な挑戦も評価する。
- 格上への勝利を大きく評価する。
- レートの完全な公平性やゼロサム性は求めない。
- 対戦ゲーム自体のルールは対象外。

## 基本仕様

- 対戦は非同期で、事前に公開された相手のentityに挑戦する。
- **レートが変動するのは挑戦者のみ**。
- レートはユーザー単位で管理する。
- 初期レートは **1,000**。整数値で管理する。
- 勝利・敗北・引き分けに応じてレートを更新する。
- 対戦相手の選び方は [対戦マッチングの設計メモ](matchmaking.md) を参照。
- レートの上限は設けず、全体的なインフレを許容する。

## レート計算

相手のレート − 挑戦者のレートを \(d\) とする。

\[
d'=\operatorname{clamp}(d,-200,200)
\]

**勝利時**

\[
W(d')=\frac{450\cdot3.6^{d'/200}-60}{13}
\]

**敗北時**

\[
L(d')=11-36\left(\frac49\right)^{d'/200}
\]

| 相手とのレート差 | 勝利 | 敗北 |
|---|---:|---:|
| −200 | +5 | −70 |
| 0 | +30 | −25 |
| +200 | +120 | −5 |

- 各試合のレート変動は小数点以下をゼロ方向に切り捨てる。
- ±200を超える対戦では、レート計算に使用する差分のみ±200に制限する。
- 引き分けはEloの期待勝率 \(p=1/(1+10^{d'/400})\) を使う。
  - 格上相手：\(\lfloor40(0.5-p)\rfloor\)
  - 格下相手：\(-\lfloor36(p-0.5)\rfloor\)
  - 同レート：変動なし
- 勝敗は最終得点で判定し、同点は引き分けとする（[対戦モードのルール](battle-mode.md)）。
- 変動量はマッチング時点の挑戦者・相手のレートで計算し、結果の保存時に挑戦者の最新のレートへ加算する。
  - 同じ挑戦者の対戦が並行しても、直列化するのは加算の反映部分だけとし、更新は失われない。
  - 対戦結果には、実際に置き換わった更新前後のレートを保存する。並行時は計算に使ったレートと異なることがある。

## 結果管理・ランキング

- 対戦結果とレート更新をトランザクションで確定する。
- 対戦結果の重複反映を防止する。
- 対戦時のentityバージョン、結果、更新前後のレートを保存する。
- ランキングはレート降順とし、同じレートは同順位とする。
- ランキングには表示名を設定し、1回以上対戦を申し込んだユーザーを掲載する。
- 挑戦回数、勝敗数、勝率、レート履歴も表示できるようにする。

## シミュレーション結果

旧マッチング方式（±200以内からランダム）での参考値：

- 平均最終レート：約1,205
- 最高レートの平均：約1,464
- 潜在実力との順位相関：約0.805
- 実力上位10人とレート上位10人の一致：平均5.6人

新しい重み付きマッチング方式は未検証。

## 方針

- **上記レート計算式をv1として暫定固定する。**
- 実運用で問題が見つかった場合に再検討する。
