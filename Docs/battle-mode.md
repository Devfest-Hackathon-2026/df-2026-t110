# 対戦モードのルール案

既存のpicolangで各ロボットを操作する、2人用の荷物運搬対戦。構文や組み込み関数は追加せず、複数ロボットの進行、衝突、納品エリア、得点を対戦エンジンで管理する。

【】で囲った項目は後から決めるパラメータとし、未定の数値は◯で表す。

## 対戦の準備

- 各プレイヤーは【各チームのロボット数◯台】を使う。
- 各ロボットにpicolangのプログラムを事前に設定し、試合中は自動実行する。
- フィールドの大きさは【フィールド幅◯マス】×【フィールド高さ◯マス】とする。
- フィールドは陸、岩、海で構成し、【初期荷物数◯個】の荷物を配置する。
- 各チームに【納品エリア幅◯マス】×【納品エリア高さ◯マス】の納品エリアを設ける。両チームのエリアは重ならない。
- ロボットの初期位置・向きと納品エリアの配置は事前に公開する。
- 納品エリアへは複数の経路から近づけるようにし、迂回路を用意する。

## ターンと行動

- 全ロボットが同じターン開始時の状態を基準に判断し、行動を同時に解決する。
- 前進、後退、左右回転、拾う、置く、掘削は、成功・失敗にかかわらず各1ターンを消費する。
- `wait(n)` はnターン待機する。地形の観測など、既存仕様で時間を消費しない処理はターンを進めない。
- 岩と海には移動できず、荷物や納品エリアの上は移動できる。

## 荷物の取得と配置

- 各ロボットが持てる荷物は1個。全ての荷物は同じ価値で、【荷物単価◯点】とする。
- `pick_up()` は前方のマスにある荷物を拾い、成功すると `true` を返す。既に荷物を持っている場合や、荷物がない場合は `false` を返す。
- 同じ荷物を複数のロボットが同時に拾おうとした場合は、チームを問わず全員が取得に失敗し、`false` を返す。荷物はその場に残る。
- `release()` は持っている荷物を前方のマスに置く。成功すると `true`、失敗すると荷物を保持したまま `false` を返す。
- 荷物は1マスにつき1個まで置ける。岩や、既に荷物があるマスには置けない。
- 同じ空きマスへ複数のロボットが同時に荷物を置こうとした場合は、全員が失敗する。
- 荷物の取得・配置の可否はターン開始時の状態で判定する。同じターンに拾われる荷物があっても、そのマスへの配置は失敗する。
- 海へ置いた荷物は消失し、投棄したロボットのチームに【投棄ペナルティ◯点】の減点を適用する。

## 納品エリアと奪取

- 納品エリアの各マスを、所有チームを持つ `goal` として扱う。
- 自軍・敵軍のどちらの納品エリアにも `release()` で荷物を置ける。敵エリアに置いた場合も、通常の配置と同じ条件で成功する。
- 納品された荷物は消去せず、置かれたマスに残る。納品エリアでも1マスにつき荷物は1個までとする。
- 納品先にロボットがいても、荷物がなければ納品できる。ロボットの衝突判定と荷物の配置判定は分けて扱う。
- 納品済みの荷物も、両チームのロボットが通常の `pick_up()` で拾える。敵ロボットの納品エリアへの立ち入りも認める。
- 得点は納品回数の累計ではなく、その時点で各チームの納品エリアに置かれている荷物の数に応じて数える。
- 荷物を置くとエリア所有チームの得点が増え、持ち出すとエリア所有チームの得点が減る。運搬中やエリア外に置かれた荷物は得点に含めない。
- 敵エリアへの納品は、納品したロボットのチームではなく、エリアを所有する敵チームの得点になる。
- 同じ荷物を拾って納品し直しても、累計で得点が増え続けることはない。

## ロボット同士の衝突

- チームを問わず、1マスに存在できるロボットは1台とする。
- 同じマスへ複数のロボットが同時に移動しようとした場合は、全員が移動に失敗する。
- 2台のロボットが同時に位置を交換しようとした場合も、両方が移動に失敗する。
- 移動先のロボットが同じターンに移動に成功して退く場合は進入できる。ただし、上記の位置交換は認めない。
- 移動に失敗するなどして、そのマスに残るロボットがいる場合は進入できない。この結果、後続のロボットの移動も失敗することがある。
- 移動に失敗した場合、`forward()` または `back()` は `false` を返す。

## 掘削

- 各ロボットの掘削回数は【各ロボットの掘削上限◯回】までとする。
- 残数は既存の `drill_durability()` で確認する。
- 壊した岩は陸になり、両チームのロボットが通れる。

## 試合終了と勝敗

- 【規定ターン数◯ターン】経過で試合を終了する。最終ターンの行動と得点の更新まで行う。
- 全ての荷物が納品エリアに置かれても試合は終了しない。規定ターンまでは奪取・再納品を続けられる。
- 最終得点は「自軍の納品エリアにある荷物の数 × 【荷物単価◯点】 − 自軍の海への投棄回数 × 【投棄ペナルティ◯点】」とする。
- 最終得点が高い側の勝利とし、同点は引き分けとする。

## picolangとの対応

- 地形と荷物の確認には既存の `search_front()`、`search_now()` と判定関数を使う。
- 自軍・敵軍のどちらの納品エリアも `is_goal(...)` で識別する。所属チームを取得する関数は追加しない。
- 納品エリアに荷物があっても、エリアの属性は維持する。観測した `terrain` に対して、`is_goal(...)` と `is_laggage(...)` の両方で判別できるものとする。
- 所持状態は `pick_up()` と `release()` の返り値をbool変数に記録して管理できる。
- 自陣への帰路は、既知の初期位置・向きと、移動の成否・回転を基に変数で管理できる。敵エリアへの配置も成功するため、`release()` の返り値だけではエリアの所属を判定できない。
- この文書は対戦ルールの草案であり、納品エリアと荷物の共存、同時行動、得点管理の実装は別途必要になる。
